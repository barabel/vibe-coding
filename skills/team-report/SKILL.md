По git текущего репозитория собираешь отчёт для менеджеров о том, что сделал каждый разработчик за период. Пользователь вставит отчёт в чат Telegram, поэтому он простой и лаконичный: задачи и то, что в них сделано, без цифр по коммитам и строкам.

Аргументы необязательны, пишутся свободным текстом в любом порядке:

- **период**: «за октябрь», «с 20.10 по 24.10», «прошлая неделя». Если период не указан, бери текущую неделю с понедельника 00:00 по сегодня;
- **разработчик**: имя или часть имени автора коммитов. Если он указан, отчёт только про него, а если нет, то про всю команду.

Доступ к GitLab и Bitrix описан в разделе «Внешние сервисы» глобального `CLAUDE.md`. Временные файлы клади в scratchpad.

## Шаги

### 1. Собрать коммиты

Выполни `git fetch --all --prune`, затем возьми коммиты периода со всех веток:

```sh
git log --all --no-merges --since="<начало> 00:00" --until="<конец> 23:59" --format="%H|%aN|%aE|%ad|%s" --date=short
```

Берутся все ветки, потому что работа, которую ещё не влили, тоже должна попасть в отчёт.

Шаг готов, когда есть список коммитов периода с авторами.

### 2. Склеить авторов

Авторы с одинаковым email считаются одним человеком, склей их без вопросов. Если имена похожи, а email разные (`Viktor Kurgashov` и `Viktor_Kurgashov`), задай пользователю один вопрос со всеми такими парами и склей те, что он подтвердит. Если похожих пар нет, ничего не спрашивай.

Если в аргументах указан разработчик, оставь только его коммиты. Если имя не нашлось или подходит нескольким авторам, спроси пользователя.

Шаг готов, когда у каждого коммита есть итоговый автор.

### 3. Разложить коммиты по задачам и статусам

Для каждого коммита определи две вещи.

**Статус.** Коммит «влит», если он достижим из `origin/main` (`git merge-base --is-ancestor <sha> origin/main`), иначе он «в работе». При squash-мерже эта проверка врёт: коммит из ветки не попадает в `main`, хотя работа влита. Поэтому для проекта в GitLab проверяй ещё и MR коммита через `GET projects/<path>/repository/commits/<sha>/merge_requests`: если MR в состоянии `merged` с target `main`, коммит считается влитым.

**Задача.** Номер задачи берётся из имени ветки: `task_27953_genplan` → 27953. Ветку коммита покажут `git branch -a --contains <sha>` или поле `source_branch` у MR из запроса выше. У влитых коммитов ветка могла быть удалена, тогда ищи номер в сообщениях merge-коммитов `main`. Если номера нет, группируй коммиты по ветке или по смыслу.

Одна задача может получить оба статуса: часть уже влита, а часть ещё лежит в ветках.

Шаг готов, когда у каждого коммита есть статус и задача или группа.

### 4. Понять, что сделано

По каждой связке «разработчик, задача, статус» прочитай сообщения коммитов и дифф каждого коммита (`git show <sha>`). Дифф открывай всегда, даже при подробном сообщении, потому что сообщение пишет сам автор и оно может обещать больше, чем есть в коде: «сделан фильтр», а в диффе только разметка без логики. Качество кода не оценивай, из диффа тебе нужно только то, что фактически изменилось. Результат формулируй по диффу одной-двумя фразами, а сообщение используй как подсказку о том, что автор хотел сделать.

Шум не описывай как работу. Шум это моки, которые закомментировали и раскомментировали обратно (в одном файле добавлено и удалено почти поровну), lock-файлы, сгенерированные файлы и чистое форматирование. Коммит, в котором только шум, в отчёт не попадает.

Шаг готов, когда у каждой связки есть фраза о результате, сверенная с диффом.

### 5. Подтянуть названия задач

Название задачи бери из Bitrix: `tasks.task.get?taskId=N` → `result.task.title`. Ответ `Task not found or not accessible` это норма, тогда оставь в отчёте только номер.

### 6. Написать отчёт

Пиши языком заказчика: что появилось на сайте или в проекте, а не как это устроено в коде. Например, «сделан блок „Архитектура“ на всех разрешениях, с анимациями появления», а не «TitleFadeUp переведён на useGSAP». Если в проекте есть `GLOSSARY.md`, пиши его термины так, как они записаны в глоссарии.

Формат рассчитан на Telegram: обычный текст, жирный только через `**`, списки через «•», без таблиц и заголовков `#`. Отдай отчёт в чат одним блоком `text`, чтобы пользователь скопировал его без потерь:

```text
**lumiere-front, 26–29.10**

**barabel**
Влито в main:
• 27953 «Главная страница»: генплан с попапами Домов и переходом в Подбор по параметрам, блок консультации, «Преимущества проекта» на всех разрешениях
В работе:
• 27953 «Главная страница»: блок «Архитектура» с анимациями, начат «Импрувмент»

**Danil**
В работе:
• 27901: Подбор по параметрам, форма фильтров и поле диапазона
```

Пиши только непустые разделы «Влито в main» и «В работе». Разработчика без коммитов за период в отчёт не включай.

После блока, уже вне его, одной-двумя строками сообщи пользователю, что ты исключил как шум, где сообщение коммита расходилось с диффом и для каких задач Bitrix не отдал название.
